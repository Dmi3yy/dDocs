# Гайд користувача

Цей гайд показує користувачам менеджера, як читати і підтримувати документацію
в dDocs. Він описує тільки дії в інтерфейсі Evolution CMS manager.

## Відкрити модуль документації

1. Увійдіть у менеджер Evolution CMS.
2. Відкрийте модуль Документація.
3. Дочекайтесь завантаження дерева ліворуч і панелі перегляду праворуч.

Стартова сторінка показує доступні джерела документації: пакети, сам dDocs і
Project Documentation.

## Переглядати документацію пакетів

1. Оберіть джерело на стартовій сторінці або в лівому дереві.
2. Розкрийте папки через chevron.
3. Оберіть документ.
4. Читайте відрендерений Markdown у правій панелі.

Vendor docs доступні тільки для читання. Щоб змінити таку документацію,
редагуйте файли в репозиторії відповідного пакета.

## Шукати документацію

1. Натисніть поле пошуку в sidebar.
2. Введіть слово з назви документа, шляху, назви пакета або вмісту.
3. Відкрийте результат із відфільтрованого дерева.
4. Очистіть поле пошуку, щоб повернути повне дерево.

dDocs пропускає файли більші за `max_file_size_kb`, щоб навігація лишалась
швидкою.

## Зрозуміти fallback мови

dDocs починає з поточної мови менеджера. Якщо такої документації немає, модуль
переходить до English, а потім до нейтральних документів.

Українська документація використовує тільки `uk`. Якщо старий manager ще віддає
legacy значення `ua`, dDocs автоматично відкриває `uk` docs.

## Перемкнути мову документації

dDocs бере мову з manager language або з налаштування `default_language`.
Змініть мову менеджера або задайте `default_language`, якщо проєкту потрібна
фіксована мова документації.

## Створити документ проєкту

1. Натисніть create document у toolbar sidebar.
2. Введіть назву документа.
3. Підтвердьте діалог.
4. dDocs створить Markdown-файл у `ProjectDocs/` і відкриє його.

Project Documentation - зона для локальної документації проєкту, яку можна
редагувати з UI.

## Створити папку проєкту

1. Натисніть create folder у toolbar sidebar.
2. Введіть назву папки.
3. Підтвердьте діалог.
4. Відкрийте нову папку в дереві.

Назви папок і документів конвертуються в безпечні імена файлів перед записом на
диск.

## Редагувати документ проєкту

1. Відкрийте документ із Project Documentation.
2. Натисніть edit у header документа.
3. Оновіть Markdown в editor.
4. Натисніть save.

dDocs оновлює індекс після збереження.

## Видалити елемент проєкту

1. Відкрийте context menu для writable елемента Project Documentation.
2. Оберіть delete.
3. Підтвердьте діалог.

Delete недоступний для vendor docs і кореневих source folders.

## Скопіювати Markdown або code

Header action копіює повний Markdown source. Copy action на code block копіює
тільки конкретний snippet.

## Оновити індекс

1. Відкрийте settings panel.
2. Натисніть refresh index.
3. Дочекайтесь оновленої кількості документів.

Оновлюйте індекс після ручних змін package docs або зміни configured docs roots.

## Завантажити документацію як Markdown

1. Відкрийте settings panel.
2. Натисніть Download Markdown.
3. Збережіть generated `.md` file.

Export включає readable document nodes із поточного dDocs index. Local relative
links та images зберігають оригінальні source paths.

## Розібратись із відсутнім документом

1. Оновіть індекс.
2. Перевірте, що extension дозволений.
3. Перевірте, що file size нижчий за `max_file_size_kb`.
4. Перевірте, що package має підтримувану структуру `docs/`.
5. Попросіть developer перевірити safe roots, якщо джерело project-specific.
