## Форма документації

Evolution CMS документацію продукту впорядковано за завданнями читача, а не за старим репозиторієм
папки.```text
evolution-cms/
  01-getting-started/
  02-using-evolution-cms/
  03-site-building/
  04-development/
  05-extras-and-packages/
  06-api-and-integrations/
  07-security-updates-operations/
  08-tutorials-recipes/
  09-community-support/
  10-reference/
```Цей базовий план містить перші сторінки документації продукту, готові до випуску.
Глибокі посилання на рівні методів, корисні навантаження маршрутів і довідка менеджера на рівні поля
відстежуються як подальші завдання документації, і їх слід додавати лише після поточного
перевірка коду.

## Політика джерела

- Поточний код Evolution CMS є джерелом правди щодо поведінки під час виконання.
- Окремий пакет `evolution-cms/installer` є джерелом правди для
  поточний потік встановлення.
– Старий архів документації залишається архівом спадщини.
- Старі посібники з компонентів не перенесено в це дерево документації продукту, оскільки
  інстальовано Extras розкривати власну документацію пакета в dDocs.
- Нотатки про найкращі практики можуть стати загальнодоступними сторінками лише після перевірки поточного коду.

## Правило навігації

Сторінки повинні використовувати стабільні відносні посилання. Коли розділ виросте, додайте маленький
рядок навігації з посиланнями `Back`, `Up` і `Next`, щоб читачі могли переходити
документів, не покладаючись лише на дерево.
