# Структура проекту

[Назад](README.md) / [Вгору](README.md) / [Далі](../10-reference/cli-reference.md)

Ця сторінка відображає поточне сховище Evolution CMS у документації
межі. Тут пояснюється, де шукати, перш ніж писати глибший менеджер, API, модель,
або сторінки операцій.

## Макет верхнього рівня

| Шлях | Відповідальність |
| --- | --- |
| `composer.json` | Метадані Composer рівня проекту та базові вимоги PHP. |
| `index.php` | Публічна точка входу для веб-запитів. |
| `core/` | Основне середовище виконання, інтеграція фреймворку, конфігурація, база даних, консоль, тести, сховище та вихідний код. |
| `manager/` | Manager точка входу, дії, процесори, подання, включення та диспетчер медіа. |
| `assets/` | Загальнодоступні активи, завантажені файли, пакетні фрагменти/плагіни/модулі/шаблони/заповнювачі TV, кеш, резервне копіювання, імпорт і експорт. |
| `views/` | Заповнювачі шару перегляду проекту. |
| `install/` | Застаріла веб-версія інсталятора CLI збережена для сумісності та налагодження. Нові документи повинні спочатку навчити автономний інсталятор. |

## Основне середовище виконання

`core/` — це основна межа часу виконання.

| Шлях | Відповідальність |
| --- | --- |
| `core/composer.json` | Основний набір залежностей середовища виконання, включаючи компоненти Illuminate, базу даних, маршрутизацію, перегляд, кеш, чергу, пошту, файлову систему, Tracy, інтеграцію Composer і поведінку пакетів при злитті. |
| `core/bootstrap.php` | Завантажувальна програма під час виконання: автозавантаження Composer, завантаження кешу `.env`, користувальницькі визначення, основні визначення, сеанси, застарілі включення та включення захисту. |
| `core/config/` | Конфігурація середовища виконання для програми, кешу, бази даних, файлових систем, журналювання, сеансу, Tracy, переглядів, піктограм, міграції та підключення спостерігачів. |
| `core/custom/` | Рівень перевизначення проекту для прикладів середовища, спеціальних вимог Composer, проміжного програмного забезпечення, визначень і маршрутів. |
| `core/database/` | Міграції, засівки та артефакти бази даних. |
| `core/factory/` | Списки середовища виконання на заводському рівні, наприклад налаштування та дії менеджера. |
| `core/functions/` | Помічники спільних функцій. |
| `core/includes/` | Сумісність включає файли під час виконання. |
| `core/lang/` | Основні мовні файли. |
| `core/modifiers/` | Підтримка аналізатора/модифікатора. |
| `core/storage/` | Згенероване сховище та кеш під час виконання. |
| `core/tests/` | Поточне покриття тестів Pest/PHPUnit для інсталяції, менеджера, ядра, утиліт підтримки, пакетів/середовища виконання та поведінки сумісності. |

## Вихідні шари

`core/src/` — поточний вихідний рівень PHP.

| Шар | Відповідальність |
| --- | --- |
| `Core.php` | Центральний об’єкт середовища виконання для конфігурації, виконання аналізатора, кешу, подій, завантаження документів і API сумісності. |
| `Parser.php` | Відтворення документів, орієнтоване на парсер, і процес сумісності. |
| `UrlProcessor.php` | Створення URL-адрес і зручне вирішення URL-адрес. |
| `Bootstrap/` | Помічники середовища та початкового завантаження. |
| `Console/` | Artisan команди для кешу, переглядів, пакетів, попередніх налаштувань, маршрутів, планування, оновлень сайту, перекладів, оновлень дерева та системних завдань. |
| `Controllers/` | Manager Контролери сторінок і екрани ресурсів/користувачів/системи. |
| `Events/` | Класи підтримки заходів. |
| `Exceptions/` | Класи винятків виконання. |
| `Extensions/` | Класи підтримки розширення. |
| `Facades/` | Аксесуари у стилі Laravel для спільних служб. |
| `Interfaces/` | Контракти для теми менеджера та абстракцій середовища виконання. |
| `Legacy/` | Рівень сумісності для старих API і поведінки аналізатора. |
| `Middleware/` | Проміжне програмне забезпечення HTTP та менеджера. |
| `Models/` | Промовисті моделі для ресурсів, елементів, користувачів, дозволів, налаштувань, подій, стану планувальника/працівника та даних дерева. |
| `Observers/` | Електропроводка моделі спостерігача. |
| `Providers/` | Постачальники послуг для авторизації, Blade, Composer, конфігурації, бази даних, подій, файлової системи, теми менеджера, пакетів, маршрутизації, сеансів, завдань, Tracy, обробки URL-адрес тощо. |
| `Services/` | Потоки обслуговування вищого рівня, включаючи служби зберігання/пакетів і системних завдань. |
| `Support/` | Допоміжні класи та помічники підтримки. |
| `Tracy/` | Інтеграція панелі налагодження. |
| `Traits/` | Спільні риси для моделей і поведінки під час виконання. |

## Manager Час виконання

`manager/` — це інтерфейс менеджера та поверхня дій.| Шлях | Відповідальність |
| --- | --- |
| `manager/actions/` | Застарілі та динамічні обробники дій менеджера. |
| `manager/processors/` | Процесори збереження/видалення/публікації/кешу/налаштувань, які змінюють дані менеджера. |
| `manager/views/` | Blade перегляди сторінок менеджера, частин, екранів налаштувань, ресурсів, модулів, користувачів і фреймів. |
| `manager/includes/` | Manager контроль доступу, перевірки конфігурації, включення синтаксичного аналізатора, заголовки, помічники налагодження та межі включення застарілих версій. |
| `manager/media/` | Manager CSS, JS, зображення, ресурси браузера та медіа-теми. |

Під час документування поведінки менеджера перевірте клас контролера/джерела та
подання менеджера або процесор, який фактично виконує дію.

## Моделі та елементи

Основний вміст і концепції елементів відображаються в моделях Eloquent:

| Концепція | Модель |
| --- | --- |
| Resource / вузол дерева документів | `SiteContent` |
| Шаблон | `SiteTemplate` |
| Template Variable | `SiteTmplvar` |
| TV-відношення шаблону | `SiteTmplvarTemplate` |
| Значення TV на ресурсі | `SiteTmplvarContentvalue` |
| Chunk | `SiteHtmlsnippet` |
| Snippet | `SiteSnippet` |
| Plugin | `SitePlugin` |
| Plugin-відношення події | `SitePluginEvent` |
| Назва події | `SystemEventname` |
| Module | `SiteModule` |
| Налаштування | `SystemSetting` |
| Користувач Manager | `User` і `UserAttribute` |
| Дозволи та групи | `Permissions`, `UserRole`, `DocumentGroup`, `DocumentgroupName` та суміжні моделі групи |

Детальна документація моделі по полях належить до API/довідкових сторінок, а не
в цьому огляді структури.

## Межі пакета та Extra

Документація продукту Evolution CMS описує спільне середовище виконання та контракти на розширення.
Встановлені Extras мають свої посібники з функцій. У dDocs є пакетна документація
читати з кореневих документів файлової системи кожного встановленого пакета та показано поруч
дерево продуктів.

Задокументуйте Extra у цьому дереві продуктів лише тоді, коли сторінка пояснює спільний доступ
Evolution CMS договір пакета, поведінка інсталятора або правило інтеграції менеджера.

## Межа встановлення

Автономний інсталятор є основним поточним потоком інсталяції. Він володіє `evo
встановити`, `Qevo самовстановлення`, `Qevo самостійне оновлення`, and `Qevo системний стан`.

Папка `install/` сховища залишається важливою для сумісності,
технічне обслуговування, заглушки встановлення та налагодження, але нові документи для встановлення для користувача
слід починати з автономного інсталятора.

## Тестові поверхні

Поточні тести доступні під `core/tests/` і охоплюють:

- поведінка встановлення та міграції;
- контракти інтерфейсу менеджера та поведінка доступу;
- кеш і команди оновлення сайту;
- підтримка утиліт і нормалізація шляху;
- поведінка сумісності для застарілих API;
- пакет/зберігання/системні потоки завдань.

Коли сторінка документації описує поведінку під час виконання, віддавайте перевагу поточному коду
шлях плюс наявний тест як підтвердження. Якщо перевірки немає, задокументуйте претензію
консервативно та позначте більш глибоку перевірку як подальшу роботу.
