# Встановлення

[Назад](requirements.md) / [Вгору](README.md) / [Далі](core-concepts.md)

Поточний рекомендований шлях встановлення – автономний Evolution CMS
Пакет інсталятора. Застарілий веб-інсталятор все ще існує в основній касі,
але сучасна документація повинна спочатку навчати автономному робочому процесу `evo`.

## Встановити інсталятор

Встановіть інсталятор глобально за допомогою Composer:

```bash
composer global require evolution-cms/installer
```

Переконайтеся, що глобальний каталог bin Composer доступний у `PATH`, а потім перевірте:

```bash
evo version
```

Під час першого запуску завантажувач PHP встановлює відповідний двійковий файл Go із GitHub
Вивільняє, перевіряє контрольні суми, зберігає двійковий файл поруч із завантажувачем і
делегує йому команду.

Ви можете попередньо встановити двійковий файл явно:

```bash
evo self-install
```

Оновіть двійковий файл інсталятора за допомогою:

```bash
evo self-update
```

Щоб перевірити локальне середовище перед встановленням, запустіть:

```bash
evo system-status
```

Команда status повертає JSON для адаптера інсталятора. Він перевіряє
операційна система, версія PHP, Composer, PDO і драйвери бази даних, JSON, MySQLi,
mbstring, cURL, підтримка зображень, дисковий простір і обмеження пам’яті.

## Створіть проект

Запустіть інтерактивний інсталятор:

```bash
evo install
```

Інсталятор проведе користувача через:

- цільовий каталог;
- підключення до бази даних;
- обліковий запис адміністратора;
- довідник керівника;
- мова установки;
- пресет проекту;
- додатковий вибір Extras.

Використовуйте інтерактивний режим, коли людина вибирає шлях проекту, налаштування,
база даних, мова та необов’язковий Extras. Використовуйте режим CLI, коли ці відповіді є
відомий заздалегідь, і встановлення має виконуватися без підказок TUI.

Для інсталяції за сценарієм:

```bash
evo install demo \
  --cli \
  --branch=3.5.x \
  --db-type=sqlite \
  --db-name=database.sqlite \
  --admin-username=admin \
  --admin-email=admin@example.com \
  --admin-password=change-me \
  --admin-directory=manager \
  --language=uk \
  --preset=evolution-cms-presets/default
```

Режим CLI потребує типу бази даних, імені бази даних, електронної пошти адміністратора та адміністратора
пароль. За замовчуванням ім’ям користувача адміністратора є `admin`, а директорією менеджера –
`manager`, мова – `en`, а попередній – `evolution`, коли ці значення
не надаються.

Повний список опцій див. [CLI Reference](../10-reference/cli-reference.md).

## Параметри бази даних

Інсталятор підтримує ці драйвери бази даних, якщо відповідне розширення PHP
є в наявності:

| Водій | Примітки |
| --- | --- |
| `sqlite` | Потрібна назва файлу бази даних. Інсталятор зберігає нормалізовані імена SQLite у каталозі бази даних проекту. |
| `mysql` | Потрібен хост, ім’я бази даних, користувач і пароль у режимі CLI, якщо параметри за замовчуванням не прийнятні. |
| `pgsql` | Потрібен драйвер PostgreSQL PDO та облікові дані підключення. |
| `sqlsrv` | Потрібен драйвер SQL Server PDO та облікові дані підключення. |

Перш ніж продовжити, інсталятор перевірить підключення до бази даних. В інтерактиві
режимі невдале підключення можна спробувати повторно. У режимі CLI невдале підключення припиняється
встановлення.

## Попередні налаштування

Інсталятор відокремлює ядро Evolution CMS від рівня проекту.

| Попередньо встановлений вхід | Значення |
| --- | --- |
| Пропущено в режимі TUI | Показати вибір стилів із публічного каталогу стилів. |
| `evolution` | Встановіть лише ядро ​​Evolution. |
| `default` | Перейти до загальнодоступного репозиторію за замовчуванням. |
| `evolution-cms-presets/default` | Скопіюйте стандартний рівень проекту після основного встановлення. |
| `owner/repository` | Перейдіть до репозиторію GitHub. |
| Git URL-адреса або локальний шлях | Використовуйте спеціальне попередньо встановлене джерело. |

Попереднє налаштування не визначає майбутню Git ідентифікацію створеного сайту. The
цільовий каталог може стати власним репозиторієм проекту.

Попередній набір може включати суфікс посилання, якщо потрібна нестандартна гілка або тег:

```bash
evo install demo --preset=evolution-cms-presets/default@dev
```

Попередні налаштування застосовуються через `core/artisan» встановленого проекту
preset:install` після того, як ядро Evolution CMS буде готове, а потім preset
міграції запускаються.

## Extras Під час встановлення

Інсталятор може інсталювати Extras після того, як основний проект буде готовий:

```bash
evo install demo --extras=sTask,sSeo
```

За потреби пакети Legacy Store можна вибрати за ідентифікатором:

```bash
evo install demo --extras=legacy-store:84@1.12.2
```

Не документуйте встановлення старого компонента як шлях за замовчуванням для поточного
проекти. Зберігайте інформацію про застарілий компонент у застарілому архіві, якщо тільки a
поточний пакет явно замінює його.

Установлений Extras повинен надати власну документацію щодо пакета. dDocs відкриває
ці документи зі встановлених джерел пакетів і показує їх поруч із продуктом
документація.

## Усунення несправностей

| Проблема | Перевірити |
| --- | --- |
| GitHub API обмеження швидкості | Встановіть `GITHUB_TOKEN` або передайте `--github-pat`. |
| Composer — це псевдонім | Встановіть `EVO_COMPOSER_BIN` на справжній виконуваний файл Composer. |
| Двійковий файл не можна встановити | Перевірте дозволи на запис для каталогу пакета інсталятора `bin`. |
| Параметр бази даних не вдається | Запустіть `evo system-status` і перевірте відповідність драйвера PDO. |
| CLI режим виходить перед встановленням | Надайте `--db-type`, `--db-name`, `--admin-email` і `--admin-password`. |
| Існуючий проект виявлено | Використовуйте `--force` лише тоді, коли ви навмисно хочете встановити в існуючий каталог. |

## Межа старого веб-інсталятора

Ядро перевірки все ще містить веб-інсталятор і сценарій встановлення CLI. Тримайте
ці документи для обслуговування, сумісності та налагодження встановлення. Новий користувач
документація повинна починатися з автономного інсталятора, якщо це не завдання
зокрема про застарілу поведінку веб-встановлення.
