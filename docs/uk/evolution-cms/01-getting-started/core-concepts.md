# Основні поняття

[Назад](installation.md) / [Вгору](README.md) / [Далі](../07-security-updates-operations/troubleshooting.md)

На цій сторінці визначено словниковий запас, який використовується поточним продуктом Evolution CMS
документація. Це коротка концептуальна карта, а не посилання на API.

## Основні умови

| Термін | Значення | Поточний код поверхні |
| --- | --- | --- |
| Manager | Автентифікований інтерфейс адміністрування, який використовується для редагування вмісту, елементів, налаштувань, користувачів, пакетів і модулів менеджера. | Manager контролери та подання під час виконання менеджера. |
| Resource | Елемент вмісту, що зберігається в дереві сайту. Ресурс може представляти сторінку, текоподібний вузол, посилання або інший тип вмісту залежно від його полів. | `EvolutionCMS\Models\SiteContent` і таблицю `site_content`. |
| Дерево документів | Ієрархічний вигляд ресурсів. Батьківський, дочірній, порядок, опублікований, видалений і стан видимості впливають на вигляд ресурсу. | `SiteContent` відносини батьків/дочірніх і таблиця закриття. |
| Шаблон | Структура макета/вмісту, призначена ресурсам. Шаблони можна підключати до Template Variables. | `EvolutionCMS\Models\SiteTemplate`. |
| Template Variable | Спеціальне визначення поля, яке можна приєднати до шаблонів і зберегти для кожного ресурсу. | `SiteTmplvar`, `SiteTmplvarTemplate` і `SiteTmplvarContentvalue`. |
| Chunk | Багаторазовий текст або елемент розмітки. Chunks зазвичай використовується для повторюваних фрагментів макета або невеликих багаторазових вихідних блоків. | `EvolutionCMS\Models\SiteHtmlsnippet`. |
| Snippet | Елемент із підтримкою PHP, який може запускати логіку та повертати вихід із шаблонів, блоків або вмісту ресурсу. | `EvolutionCMS\Models\SiteSnippet`. |
| Plugin | Керований подіями код PHP, пов’язаний з однією або кількома системними подіями. Plugins реагує на події життєвого циклу менеджера, синтаксичного аналізатора, кешу, документів і розширень. | `EvolutionCMS\Models\SitePlugin` і `SitePluginEvent`. |
| Подія | Іменований хук, викликаний середовищем виконання. Події зберігаються як імена та підключаються до плагінів із пріоритетом. | `EvolutionCMS\Models\SystemEventname` і `evo()->invokeEvent(...)`. |
| Module | Інструмент або поверхня програми на стороні менеджера. Modules можна запускати з менеджера та належати до пакетів. | `EvolutionCMS\Models\SiteModule`. |
| Пакет | Composer-розповсюджений пакет коду, який може надавати служби, перегляди, маршрути, конфігурацію, активи, модулі та документацію. | Пакунки Composer плюс команди/служби пакету Evolution. |
| Extra | Додатковий пакет або розширення, інстальоване в проект. Extras володіє власною документацією щодо пакетів у dDocs. | Встановлені джерела пакетів, індексовані dDocs. |
| Кеш | Згенеровані дані часу виконання, які використовуються синтаксичним аналізатором, менеджером, представленнями даних, метаданими пакетів і налаштуваннями. Кеш можна очистити з менеджера або консолі. | `evo()->clearCache('full')`, `cache:clear-full` та оновлення сайту. |

## Як вони поєднуються

Типова сторінка починається як ресурс у дереві документів. Ресурс вибирає a
Шаблон. Шаблон може розкривати Template Variables для структурованих полів.
Шаблони Chunks і Snippets можуть створювати вихідні дані. Plugins слухати події
розширити поведінку під час виконання. Modules надає інструменти на стороні менеджера для більших робочих процесів.

```text
Resource -> Template -> TV values
         -> Chunks and Snippets
         -> Plugins through Events
         -> Cache and rendered output
```

## Документи продуктів і пакетів

Evolution CMS Документація продукту пояснює основні концепції продукту, менеджер
поведінка, архітектура середовища виконання, API, операції та межі оновлення.

Встановлені Extras задокументовані власними пакетами. dDocs читає ці пакети
docs із файлової системи та показує їх поруч із документацією продукту. робити
не копіюйте повні посібники Extra у це дерево продуктів, якщо на сторінці немає пояснень
договір про основну інтеграцію, спільний для всіх пакетів.

## Межі спадщини

Evolution CMS все ще містить поверхні сумісності для старого коду та старого
монтажні потоки. Поточна документація має називати ці поверхні лише тоді, коли a
читач повинен розуміти поведінку сумісності або міграції. Нові підручники
інструкції повинні починатися з поточного інсталятора, пакета, менеджера та
Робочі процеси на основі Composer.
