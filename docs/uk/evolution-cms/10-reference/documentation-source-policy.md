# Політика щодо джерел документації

[Назад](documentation-navigation.md) / [Вгору](../README.md)

Документація Evolution CMS має описувати поточну поведінку продукту. Історичний
матеріал може допомогти, але він не є канонічним, доки його не перевірять за поточними
код.

## Дозволені джерела

| Джерело | Використовуйте |
| --- | --- |
| Поточний код Evolution CMS | Середа виконання, менеджер, API, моделі, конфігурація, події, CLI, сумісність інсталятора та межі застарілих версій. |
| Код окремого інсталятора та README | Поточний потік інсталяції та поведінка команди `evo`. |
| Старий архів документів Evolution CMS | Класичний API, DB API, термінологія та історична поведінка після перевірки. |
| Перевірені рекомендації | Майбутні рецепти після перевірки поточної маршрутизації, моделі та API менеджера. |
| Пакетна документація | Пов’язано, коли підтримуваний Extra володіє деталями пакета. |

## Матеріал не перенесено

Старі посібники з компонентів не копіюються в це дерево документів продукту. Вони залишаються всередині
спадковий архів. Поточні встановлені Extras відображаються в dDocs через власні
документація на рівні пакета.

## Правило огляду

Коли використовується історичний матеріал або матеріал передового досвіду:

1. Перевірте поточний шлях коду.
2. Перевірте, чи є функція поточною, застарілою чи застарілою.
3. Перепишіть сторінку для поточного завдання читача.
4. Посилання на пакети документів замість копіювання посібників пакетів.
5. Зберігайте старі сторінки компонентів як архівний матеріал.

## Майбутні передові теми

Перші кандидати:

- маршрути, запити Ajax, перевірка запитів, відповіді JSON і Blade частково
  візуалізація;
- Використання моделі `SiteContent`, запити TV, обхід дерева закриття та ресурс
  відбір шаблонів.

Вони належать після того, як базова документація буде достатньо точною для їх підтримки
після перевірки прикладів на поточний код.
