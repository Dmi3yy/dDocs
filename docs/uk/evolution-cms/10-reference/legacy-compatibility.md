# Довідник із сумісності із застарілими версіями

[Назад](core-composer.md) / [Вгору](../README.md) / [Далі](artisan-commands.md)

Evolution CMS зберігає застарілий рівень сумісності, щоб підтримувати поточний код
класичні API Evolution, поведінка аналізатора, дії менеджера та старіші розширення
шаблонів, а середовище виконання використовує сучасні компоненти PHP і Illuminate.

## Застарілий вихідний рівень

| Файл або клас | Відповідальність |
| --- | --- |
| `core/includes/legacy.inc.php` | Включено Bootstrap для сумісності зі старими версіями. |
| `Legacy/DeprecatedCore.php` | Застаріла поведінка сумісності ядра. |
| `Legacy/ManagerApi.php` | Поверхня сумісності Manager action/API. |
| `Legacy/TemplateParser.php` | Сумісність аналізатора шаблонів. |
| `Legacy/Modifiers.php` | Підтримка модифікатора парсера та умовного модифікатора. |
| `Legacy/Phx.php` | Сумісність заповнювачів/модифікаторів у стилі PHx. |
| `Legacy/Cache.php` | Поведінка перебудови/оновлення застарілого кешу. |
| `Legacy/Permissions.php` | Поведінка сумісності дозволів користувача/документа. |
| `Legacy/ErrorHandler.php` | Застаріла обробка помилок. |
| `Legacy/LogHandler.php` | Застаріла поведінка журналювання. |
| `Legacy/PasswordHash.php` | Сумісність із хешуванням старих паролів. |
| `Legacy/PhpCompat.php` | PHP помічники сумісності. |
| `Legacy/Categories.php` | Поведінка сумісності категорій. |
| `Legacy/ModuleCategoriesManager.php` | Поведінка сумісності категорії Module. |
| `Legacy/mgrResources.php` | Manager Сумісність допоміжних ресурсів/елементів. |

## Застарілі постачальники

Список постачальників програм реєструє постачальників сумісності для застарілих
основна поведінка, DB API, менеджер API, модифікатори, хешування пароля, PHx,
DLTemplate, ModResource, ModUsers, помічники файлової системи та відповідна підтримка.

Ці постачальники зберігають доступними класичні API, тоді як новіший код використовує поточний
послуги, моделі, контролери та фасади.

## Legacy включає та помічники

Core Composer автоматично завантажує допоміжні файли/файли дій, які зберігають старіші функції
поверхні:

| Площа | Автоматичне завантаження файлів |
| --- | --- |
| Manager помічники дій | `functions/actions/*.php` для файлового менеджера, налаштувань, зміни вмісту, плагінів, журналювання, довідки та поведінки менеджера резервного копіювання. |
| Помічники виконання | `functions/helper.php`, `functions/laravel.php`, `functions/utils.php` |
| Дерево і вузли | `functions/nodes.php` |
| Попереднє завантаження і процесори | `functions/preload.php`, `functions/processors.php` |

Новий код має віддавати перевагу поточним службам і моделям, але документація повинна
визнати, що ці функціональні поверхні все ще існують.

## Застарілі дії Manager

Менеджер все ще містить обробники дій і процесори:

| Поверхня | Призначення |
| --- | --- |
| `core/factory/actionlist.php` | Застаріла карта ID дії. |
| `manager/actions/` | Застарілі та динамічні обробники сторінок/дій. |
| `manager/processors/` | Зміна процесорів для збереження, видалення, публікації, кешу, налаштувань, ролей, модулів, користувачів і елементів. |
| `ManagerTheme` | Вирішує активну дію/поведінку теми контролера та менеджера. |
| Модельні карти дій | Надайте ідентифікатори дій редагування/нового/збереження/видалення/запуску для екранів на основі моделі. |

Під час документування функції менеджера перевірте ідентифікатор дії, контролер/дію
файл, процесор і Blade переглядати разом.

## Сумісність парсера

Класичні функції аналізатора залишаються частиною поточного середовища виконання:

| Особливість | Примітки |
| --- | --- |
| Теги Resource | Синтаксис полів `[*field*]` і TV. |
| Теги налаштувань | `[(setting)]`. |
| Chunks та фрагменти | `{{chunk}}`, `[[snippet]]` і `[!snippet!]`. |
| Заповнювачі | `[+placeholder+]` з поведінкою PHx/модифікатора. |
| Теги URL | `[~id~]`. |
| Умовні теги | `<@IF:...>`, `<@ELSEIF:...>`, `<@ELSE>`, `<@ENDIF>`. |
| Режими шаблону | `@CODE`, `@FILE`, `@DOCUMENT`, `@B_FILE` і `@B_CODE`. |

Використовуйте [Довідник тегів аналізатора](parser-tags.md) для отримання деталей синтаксису.

## Що не можна переходити наосліп

Не копіюйте старі посібники з компонентів у документацію продукту лише тому, що
застарілий рівень все ще існує. Старі компоненти, старі фрагменти та старіші сайтобудівники
шаблони повинні залишатися в архіві застарілих версій, якщо їх не перевірено на відповідність
поточний код і досі представляють рекомендоване використання.

Встановлені Extras надають власні документи як окремі джерела dDocs.

## Правило документаціїПід час документування застарілої поведінки позначте її як сумісність, якщо це не є
рекомендований поточний шлях. З’єднайте успадковані претензії з поточними посиланнями на код і
уникайте перетворення старих API на нові приклади найкращої практики.
