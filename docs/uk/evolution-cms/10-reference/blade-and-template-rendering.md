# Blade і довідка про візуалізацію шаблону

[Назад](roles-and-permissions.md) / [Вгору](../README.md) / [Далі](parser-tags.md)

Evolution CMS підтримує як класичні шаблони аналізатора Evolution, так і Blade
шаблони. Поточне середовище виконання вибирає шлях відтворення з ресурсу
шаблон і доступне відображення перегляду Blade.

## Потік візуалізації

| Крок | Поведінка під час виконання |
| --- | --- |
| Завантажити ресурс | Core завантажує об’єкт ресурсу, перевіряє видалений/опублікований/посилальний стан і готує дані документа. |
| Вирішити шаблон | Середа виконання запитує процесор шаблонів про перегляд документа Blade. Якщо жодного немає, він завантажує код шаблону з бази даних. |
| Обмін даними | Шаблони Blade отримують `modx`, `documentObject` і переглядають дані із середовища виконання. |
| Рендер Blade | Якщо представлення Blade існує, воно рендериться фабрикою представлень, а ресурс розглядається як такий, що не кешується для цього проходу. |
| Розібрати класичний шаблон | Якщо подання Blade не існує, класичний код шаблону аналізується аналізатором Evolution. |
| Викликати події | `OnLoadWebDocument` запускається після підготовки вмісту документа. Вихідні події та поведінка після аналізу запускаються пізніше в потоці відповіді. |

Якщо ресурс не має призначеного шаблону, середовище виконання використовує `[*content*]` як a
пустий класичний шаблон.

## Джерела шаблонів

| Джерело | Синтаксис або поверхня | Примітки |
| --- | --- | --- |
| Шаблон бази даних | Manager Елемент шаблону | Класичний шаблон аналізатора Evolution. |
| Blade перегляд документа | Вирішений процесор шаблону | Поточний шлях Blade для шаблонів ресурсів. |
| Файл шаблону, створений під час збереження | Варіант шаблону Manager | Збереження шаблону може створити відповідний файл `.blade.php`. |
| `@FILE` режим послідовності/шаблону | `@FILE:path` | Читає файл шаблону за налаштованим шляхом і розширенням шаблону. |
| `@CODE` / `@INLINE` / `@TPL` | Рядок вбудованого коду | Використовується помічниками фрагментів/шаблонів аналізатора. |
| `@DOCUMENT` / `@DOC` | Вміст документа за ідентифікатором або поточним документом | Витягує вміст документа в шаблони аналізатора. |
| `@B_FILE` | Режим файлу Blade | Відтворює файл Blade через клоновану фабрику переглядів. |
| `@B_CODE` | Режим коду Blade | Записує згенерований файл кешу Blade і відображає його через простір імен `cache::`. |

## Blade Дані

Blade шаблони документів отримують поточний об’єкт виконання та дані документа.

| Змінна | Значення |
| --- | --- |
| `$modx` | Поточний Evolution CMS основний об’єкт/об’єкт виконання. |
| `$documentObject` | Поточні дані об'єкта ресурсу. |
| Переглянути дані | Додаткові дані про час виконання, підготовлені `getDataForView()`. |

Коли процесор фрагментів `DLTemplate` активний, ті самі спільні дані також є
перейшов у свою інтеграцію Blade.

## Manager Blade Перегляди

Інтерфейс менеджера використовує подання Blade у просторі імен подання менеджера.

| Переглянути шаблон | Призначення |
| --- | --- |
| `manager::template.page` | Стандартна оболонка сторінки менеджера. |
| `manager::template.blank` | Мінімальна оболонка сторінки менеджера. |
| `manager::partials.header` | Manager активи заголовків і верхній стек сценаріїв. |
| `manager::partials.footer` | Manager нижній і нижній стеки сценаріїв. |
| `manager::partials.actionButtons` | Стандартні кнопки дій на сторінці менеджера. |
| `manager::form.*` | Спільний менеджер форм рядків, вводів, радіокерування, вибору та текстових областей. |
| `manager::page.*` | Manager екрани сторінок і вкладені частини сторінок. |

Звичайні стеки Blade, які використовуються переглядами менеджера, включають `scripts.top` і
`scripts.bot`.

## Основні директиви Blade

| Директива | Вихід |
| --- | --- |
| `@evoConfig($key)` | Екрановані значення з `evo()->getConfig($key)`. |
| `@makeUrl($value)` | Екранована URL-адреса, згенерована процесором URL-адрес. |
| `@evoParser($value)` | Проаналізовано вміст Evolution через `evo_parser()`. |
| `@evoRole($role)` | Відкриває умовний блок, якщо `evo_role($role)` має значення true. |
| `@evoElseRole($role)` | Додає гілку `elseif` для іншої перевірки ролі. |
| `@evoEndRole` | Закриває умовний блок ролі. |
| `@auth` | Правда, коли `evo()->getLoginUserID()` не є хибним. |
| `@guest` | Правда, коли жоден зовнішній користувач не ввійшов у систему. |
| `@svg($name, ...)` | Відтворює Blade Icons SVG через адаптер Evolution. |Застарілі спеціальні директиви все ще можна зареєструвати з `view.directive`, але
цей шлях є застарілим і не повинен використовуватися для документації нового продукту.

## Помічники директив підтримки

Допоміжний клас підтримки також визначає зворотні виклики застарілих директив, які використовуються старішими
реєстрація керованої конфігурацією директиви:

| Помічник | Значення |
| --- | --- |
| `csrf()` | Виводить поле CSRF. Застаріле. |
| `evoLang($key)` | Читає значення словника менеджера. |
| `evoStyle($key)` | Читає значення стилю менеджера. |
| `evoAdminLang()` | Читає назву мови активного менеджера. |
| `evoCharset()` | Читає кодування менеджера. |
| `evoAdminThemeUrl()` | Читає URL-адресу теми менеджера. |
| `evoAdminThemeName()` | Читає назву теми менеджера. |

Нові сторінки адміністратора мають надавати перевагу поточним помічникам менеджера та спільним переглядам
додавання нових керованих конфігурацією директив.

## Blade Значки

Evolution CMS постачає адаптер для піктограм Blade. Адаптер:

- об'єднує основну конфігурацію `blade-icons`;
- реєструє фабрику ікон і маніфест;
- реєструє директиву `@svg`;
- реєструє компоненти значка, коли існує маніфест значка;
- публікує конфігурацію `blade-icons.php` в режимі консолі.

Використовуйте піктограми за допомогою налаштованих наборів піктограм і зберігайте назви піктограм інтерфейсу менеджера стабільними
коли на них посилаються документи пакетів або знімки екрана.

## Правило документації

Під час документування поведінки шаблону вкажіть, чи є приклад класичним парсером
синтаксис або синтаксис Blade. Не змішуйте теги аналізатора та директиви Blade в одному
приклад, якщо сторінка явно не пояснює, як взаємодіють два шляхи відтворення.
