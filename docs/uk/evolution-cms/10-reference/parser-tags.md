# Довідка про теги аналізатора

[Назад](blade-and-template-rendering.md) / [Вгору](../README.md) / [Далі](models.md)

Класичні шаблони Evolution CMS використовують теги аналізатора для ресурсів, налаштувань,
блоки, фрагменти, заповнювачі, URL-адреси та умовний вміст. Ця сторінка записує
поточна поверхня основного тегу, щоб приклади залишалися послідовними.

## Стандартні теги

| Тег | Значення | Приклад |
| --- | --- | --- |
| `[*field*]` | Поточне поле ресурсу або Template Variable. | `[*pagetitle*]` |
| `[(setting)]` | Системне налаштування або значення конфігурації середовища виконання. | `[(site_name)]` |
| `{{chunk}}` | Вміст Chunk. | `{{site_header}}` |
| `{{chunk?&name=`значення`}}` | Chunk з локальними параметрами. | `{{card?&title=`Привіт`}}` |
| `[[snippet]]` | Виклик кешованого фрагмента. | `[[DocLister]]` |
| `[!snippet!]` | Виклик некешованого фрагмента. | `[!contactForm!]` |
| `[+placeholder+]` | Значення заповнювача з області аналізатора. | `[+title+]` |
| `[~id~]` | Resource URL. | `[~1~]` |
| `[^key^]` | Стиль виконання/метазаповнювача, який використовується шляхом очищення та екранування. | `[^q^]` |

Під час документування використовуйте виділені приклади з мовними мітками `html` або `blade`
код шаблону в Markdown.

## Resource поля та TVs

Теги Resource спочатку зчитують поточний об’єкт документа. Вони також вміють читати
Template Variables, коли значення TV завантажуються для ресурсу.

```html
<h1>[*pagetitle*]</h1>
<p>[*introtext*]</p>
<img src="[*hero_image*]" alt="">
```

Синтаксичний аналізатор також підтримує пошук контексту за допомогою `@` у тегах ресурсів. поточний
обробка контексту включає батьківський елемент, остаточний батьківський елемент, пошук псевдонімів, попередній/наступний
пошук брата та прямий пошук ідентифікатора ресурсу.

```html
[*pagetitle@parent*]
[*pagetitle@uparent(0)*]
[*pagetitle@alias(home)*]
```

## Налаштування системи

Теги налаштувань зчитують конфігурацію середовища виконання та відомі значення шляху/url.

```html
<title>[(site_name)]</title>
<base href="[(site_url)]">
```

Загальні генеровані значення включають `base_url`, `base_path`, `site_url`,
`valid_hostnames`, `site_manager_url` і `site_manager_path`.

## Chunks

Chunks — це багаторазові шаблони. Параметри, передані в фрагмент, доступні як
локальні заповнювачі під час аналізу блоку.

```html
{{button?&label=`Read more`&url=`[~12~]`}}
```

Вихідні дані Chunk можуть містити заповнювачі, теги ресурсів, налаштування, інші блоки,
і умовні теги. Синтаксичний аналізатор рекурсивно вирішує вкладений вміст, поки не буде
досягнуто налаштованого ліміту пропуску аналізатора.

## Snippets

Кешовані фрагменти використовують `[[...]]`. Некешовані фрагменти використовують `[!...!]` і перетворюються
для тегів фрагментів під час виведення після аналізу.

```html
[[menuBuilder?&startId=`0`]]
[!contactForm?&redirectTo=`15`!]
```

Параметри Snippet аналізуються перед виконанням. Зберігайте значення параметрів явними
і уникайте покладатися на незадокументований глобальний стан.

## Заповнювачі

Заповнювачі вирішуються з поточної області заповнювача парсера або локально
дані, передані у виклик фрагмента/парсера.

```html
<article>
  <h2>[+title+]</h2>
  <p>[+summary+]</p>
</article>
```

Заповнювачі можуть використовувати модифікатори. Модифікатори є частиною класичного аналізатора
поверхні та мають бути задокументовані з характеристикою, яка залежить від них.

## Теги URL

URL-теги переписуються під час обробки виводу.

```html
<a href="[~1~]">Home</a>
```

Вивід URL-адреси залежить від стану публікації ресурсу, зручних налаштувань URL-адреси,
псевдоніми, суфікси, базову URL-адресу та процесор URL-адрес.

## Conditional Tags

Умовні теги вмикаються через налаштування `enable_at_syntax`. поточний
основний синтаксис використовує теги у верхньому регістрі:

```html
<@IF:[*published*]>
  Published
<@ELSE>
  Draft
<@ENDIF>
```

Парсер також нормалізує старі форми коментарів HTML, такі як `<!--@IF ...-->`,
`<!--@ELSE-->` і `<!--@ENDIF-->`.

## Прив'язки та вбудовані режими шаблонів

Помічники шаблону аналізатора розпізнають спеціальні режими:

| Режим | Значення |
| --- | --- |
| `@CODE` / `@INLINE` / `@TPL` | Використовуйте вбудований код шаблону. |
| `@FILE` | Завантажте код шаблону з файлу за налаштованим шляхом до шаблону. |
| `@DOCUMENT` / `@DOC` | Завантажити вміст з поточного або вибраного ресурсу. |
| `@B_FILE` | Відобразити файл Blade. |
| `@B_CODE` | Візуалізуйте вбудований код Blade через згенерований кеш. |
| `@T_CODE` / `@T_FILE` | Зарезервовані режими шаблону в обробці аналізатора. |

Див. [Blade і довідку про візуалізацію шаблонів](blade-and-template-rendering.md)
для поведінки, специфічної для Blade.

## Очищення та втеча

Вихідний потік може:

- запускати некешовані фрагменти під час пост-парсингу;
- вводити зареєстровані сценарії запуску перед `</head>`;
- вводити зареєстровані сценарії перед `</body>`;
- очистити невикористані теги Evolution;
- переписати URL-теги в кінцеві URL-адреси.

`getTagsForEscape()` включає стандартні пари тегів, такі як `{{ }}`, `[[ ]]`,
`[! !]`, `[* *]`, `[( )]`, `[+ +]`, `[~ ~]` і `[^ ^]`.

## Правило документації

Під час написання прикладів використовуйте найменшу поверхню тегів, яка пояснює завдання. для
нові проекти, які використовують шаблони Blade, віддають перевагу прикладам Blade і посилаються лише тут
коли потрібні класичні теги аналізатора.
