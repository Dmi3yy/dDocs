# Artisan Довідка про команди

[Назад](legacy-compatibility.md) / [Вгору](../README.md) / [Далі](models.md)

Ця сторінка документує командну поверхню встановленого проекту Artisan, зареєстровану
поточне ядро Evolution CMS. Він окремий від автономного інсталятора
Команда `evo`, задокументована в [CLI Reference](cli-reference.md).

## Консольне середовище виконання

Evolution CMS використовує спеціальну консольну програму, яка:

- використовує дані версії Evolution CMS як назву консольної програми;
- відключає автоматичний вихід і перехоплення винятків;
- створює об'єкт запиту з налаштованої URL-адреси сайту для контексту консолі;
- відправляє початкову подію Artisan;
- завантажує відкладені провайдери та команди початкового завантаження.

Виконайте ці команди з контексту виконання встановленого проекту `core/`, якщо тільки a
команда явно приймає цільовий шлях.

## Кеш і перегляди

| Команда | Призначення |
| --- | --- |
| `cache:clear` | Очистіть налаштоване сховище кешу Illuminate. |
| `cache:forget` | Видаліть один ключ із налаштованого сховища кешу. |
| `cache:clear-full` | Очистити скомпільований кеш Blade/view і поверхні кешу Evolution. |
| `clear-compiled` | Видаліть скомпільований файл класу. |
| `view:clear` | Очистити скомпільовані файли перегляду Blade. |

## База даних і розсівачі

| Команда | Призначення |
| --- | --- |
| `migrate` | Виконайте міграції бази даних. |
| `migrate:fresh` | Видалити всі таблиці та повторно запустити міграції. |
| `migrate:install` | Створіть репозиторій міграції. |
| `migrate:refresh` | Скинути та повторно запустити міграції. |
| `migrate:reset` | Відкотити всі міграції. |
| `migrate:rollback` | Відкотити останній пакет міграції. |
| `migrate:status` | Показати статус міграції. |
| `make:migration` | Створіть файл міграції. Команда розвитку. |
| `db:seed` | Запустити сівалки. |

Розглядайте деструктивні команди міграції як операційні завдання. Вони можуть знищити дані
при запуску з неправильною базою даних.

## Списки та діагностика

| Команда | Призначення |
| --- | --- |
| `doc:list` | Перелік документів/ресурсів з `site_content`. |
| `tpl:list` | Список шаблонів із `site_templates`. |
| `tv:list` | Список Template Variables. |
| `deprecated:list` | Перелічіть застарілі маркери та додаткові теги видалення/версії. Команда розвитку. |
| `route:list` | Список зареєстрованих маршрутів. |

Ці команди корисні для перевірки документації, оскільки вони відкривають
поточні об’єкти середовища виконання, не покладаючись на старі посібники.

## Пакети та Extras

| Команда | Підпис | Призначення |
| --- | --- | --- |
| `package:discover` | `package:discover` | Створення даних виявлення постачальника послуг для спеціальних пакетів. |
| `package:create` | `package:create {packagename?}` | Створіть пакетний каркас. |
| `package:runconsoles` | `package:runconsoles` | Виконуйте консольні команди з настроюваних пакетів. |
| `package:installrequire` | `package:installrequire {key} {value} {composer_run=1}` | Додайте вимогу Composer до вимог спеціального пакета. |
| `package:removerequire` | `package:removerequire {key} {composer_run=1}` | Видаліть вимогу Composer із вимог спеціального пакета. |
| `package:installautoload` | `package:installautoload {key} {value} {composer_run=1}` | Додайте запис автозавантаження до вимог спеціального пакета. |
| `extras` | `extras {typePackage?} {packageName?} {versionPackage?} {namePackage?} {--list} {--json}` | Перегляньте або встановіть Extras/packages залежно від аргументів. |

Установлені Extras мають задокументувати свої команди, що стосуються окремих пакетів, у своєму
власні пакети документів. Ця сторінка документує основну командну поверхню, яка відкриває
і керує пакетами.

## Попередні налаштування

| Команда | Призначення |
| --- | --- |
| `preset:install` | Встановіть стиль зі сховища Git або локального шляху. |
| `preset:apply` | Застосуйте попередньо встановлений рівень проекту до встановлення Evolution CMS. |

`preset:apply` підтримує параметри цільового шляху, вихідного шляху, Git джерело/посилання,
збереження клонованих джерел, попередньо встановлене ім'я, видалення файлів, яких немає в попередньому наборі,
сухий режим, примусові сівалки та пропуск Composer dump-autoload.

## Планування та системні завдання| Команда | Призначення |
| --- | --- |
| `schedule:list` | Список запланованих команд. |
| `schedule:run` | Виконати заплановані команди. |
| `schedule:work` | Запустіть робочий цикл планувальника. |
| `schedule:finish` | Позначити заплановану подію як завершену. |
| `schedule:clear-cache` | Очистити стан м'ютексу/кешу планувальника. |
| `schedule:test` | Перевірте заплановану команду. |
| `system:scheduler-heartbeat` | Записувати стан серцебиття планувальника. |
| `system:task-worker` | Записуйте дії системного працівника завдань і готуйте виконання завдань у черзі. |

Команди системних завдань є командами виконання операцій. Виробничі документи повинні
включити нагляд за процесом і політику журналювання, перш ніж рекомендувати завжди ввімкнути
робітників.

## Обслуговування сайту та проекту

| Команда | Призначення |
| --- | --- |
| `make:site` | Оновлення/збірка об’єктів сайту з налаштованих джерел. |
| `closuretable:rebuild` | Перебудуйте таблицю закриття дерева ресурсів. |
| `translations:sync` | Синхронізувати ключі перекладу з мовним файлом за замовчуванням. |
| `tailwind:build {package?} {--force}` | Скомпілюйте Tailwind CSS для одного пакета, усіх пакетів або примусового відновлення. |
| `vendor:publish` | Публікуйте доступні для публікації ресурси постачальника. Команда розвитку. |

`make:site` і `closuretable:rebuild` впливають на стан виконання. Використовуйте резервні копії та a
відомий потік розгортання перед запуском у виробництві.

## Команди розробки

Команди розробки включають `vendor:publish`, `deprecated:list` і
`make:migration`. Вони зареєстровані тим самим постачальником послуг, але мають бути
задокументовані як інструменти розробки/обслуговування, а не як звичайні робочі процеси менеджера.

## Правило документації

Під час документування команди включіть:

- назва/підпис команди;
- контекст виконання;
- чи читає чи змінює стан проекту;
- чи безпечний він для виробництва;
- пов'язана конфігурація або межа Composer.

Не документуйте в цьому довідковому документі поведінку команди, що залежить від пакета
якщо команда не зареєстрована ядром Evolution CMS.
