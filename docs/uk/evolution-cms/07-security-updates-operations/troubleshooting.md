# Усунення несправностей

[Назад](../01-getting-started/core-concepts.md) / [Вгору](README.md) / [Далі](../10-reference/source-inventory.md)

Використовуйте цю сторінку для першої перевірки перед відкриттям глибшого коду або хостингу
діагностика. Він зосереджений на поточному Evolution CMS та поведінці інсталятора.

## Швидкі перевірки

| Симптом | Перевірте спочатку |
| --- | --- |
| Інсталятор не запускається | Перевірте PHP 8.3 або новішу версію, наявність Composer і доступний для запису бінарний каталог інсталятора. Запустіть `evo system-status`, коли доступно. |
| Інсталятор не може завантажити чи оновити двійковий | Перевірте доступ до мережі до випусків GitHub. Якщо швидкість обмежена, установіть `GITHUB_TOKEN` або передайте параметр інсталятора GitHub маркера. |
| Composer не знайдено | Переконайтеся, що Composer є виконуваним файлом на `PATH`, а не лише псевдонімом оболонки. Встановіть `EVO_COMPOSER_BIN`, коли хосту потрібен явний шлях Composer. |
| Помилка налаштування бази даних | Переконайтеся, що вибраний драйвер бази даних встановлено для PHP, хост/порт/ім’я/користувач/пароль правильні, а імена SQLite дійсні для каталогу бази даних проекту. |
| Встановлення завершено, але не вдалося ввійти менеджеру | Перевірте каталог менеджера, вибраний під час інсталяції, поведінку сеансу/файлів cookie, записи користувачів бази даних і чи команда інсталяції повідомляла про резервні попередження адміністратора користувача. |
| Сторінка порожня або повертає помилку сервера | Перевірте журнали помилок PHP, журнали програм, відсутні залежності Composer і чи потрібно повне оновлення згенерованих кешів. |
| Зміни не видно на сайті | Очистіть повний кеш або запустіть дію оновлення сайту. Кешування Resource, кеш перегляду, кеш env і кеш браузера можуть приховати останні зміни. |
| Дружні URL-адреси не працюють | Переконайтеся, що `friendly_urls` увімкнено, правила перезапису налаштовано на веб-сервері, псевдоніми дійсні та кеш оновлено. |
| Переглядач файлів або помилка завантаження | Перевірте `filemanager_path`, `rb_base_dir`, налаштування розширення завантаження, максимальний розмір завантаження та дозволи файлової системи для цільових каталогів. |
| Керуючий користувач не може побачити документ | Перевірте дозволи менеджера, групи документів, групи користувачів, позначки конфіденційності ресурсу та чи має користувач доступ до дії менеджера. |
| У dDocs | відсутня документація пакета Переконайтеся, що пакет містить папку файлової системи `docs/`, пакет встановлено в проекті, dDocs оновлено, а поточна мова менеджера відповідає доступній локалі документів. |
| Функція, специфічна для Extra, тут не задокументована | Відкрийте Extra у dDocs. Документація продукту описує спільну поведінку Evolution CMS; встановлені Extras володіють своїми посібниками з функцій. |

## Кешувати та оновлювати

Загальний шлях повного оновлення викликає `evo()->clearCache('full')`. Менеджер сайту
refresh також публікує та скасовує публікацію запланованих ресурсів, очищає повний кеш,
видаляє згенерований кеш env, якщо він присутній, і викликає подію оновлення сайту.

Використовуйте оновлення кешу після змін:

- шаблони, блоки, фрагменти, плагіни, модулі або Template Variables;
- системні параметри, які впливають на маршрутизацію, шляхи, завантаження, кеш або вивід менеджера;
- пакети постачальників послуг, активи, перегляди або згенерована конфігурація;
- псевдоніми ресурсів, опублікований стан, дозволи або налаштування зручних URL-адрес.

## Перелік дружніх URL-адрес

Проблеми з дружньою URL-адресою зазвичай стосуються як параметрів Evolution CMS, так і веб-сервера
конфігурація.

| Площа | Що перевірити |
| --- | --- |
| Налаштування Manager | `friendly_urls`, налаштування суфікса/префікса, поведінка папки, строгі налаштування URL-адреси та псевдоніми. |
| Веб-сервер | Для проекту активні правила перезапису Apache або еквівалентна маршрутизація Nginx. |
| Resources | Псевдоніми є унікальними, де це необхідно, а ресурси публікуються, видимі та не видаляються. |
| Кеш | Оновіть сайт після зміни псевдонімів, налаштувань URL-адреси або поведінки перезапису. |

## Контрольний список файлів і завантажень

Проблеми з диспетчером файлів і завантаженням зазвичай виникають через шляхи, дозволені списки розширень або
дозволи.| Область налаштування | Що перевірити |
| --- | --- |
| Шлях до файлового менеджера | Налаштований шлях вказує всередину проекту та читається PHP. |
| Resource базовий каталог браузера | Базовий каталог браузера вказує на передбачуване розташування активів. |
| Завантажити розширення | Файли, зображення та списки розширень медіафайлів дозволяють очікуваний тип файлу. |
| Розмір завантаження | Обмеження завантаження Evolution CMS і обмеження завантаження PHP/веб-сервера достатньо високі. |
| Дозволи | PHP може створювати, записувати, перейменовувати та видаляти файли в цільовому каталозі. |

## Межа документації пакета

dDocs — це поверхня документації пакета для встановленого Extras. Якщо пакет
відображається в дереві dDocs лише з назвою пакета або без локалізованих сторінок,
виправити джерело документації пакунка, а не копіювати його посібник
Evolution CMS документація продукту.

Для проблем із пакетними документами перевірте:

- пакет містить `docs/en/README.md` або інший підтримуваний запис про мову;
- українські документи пакетів використовують папку локалі `uk`; застаріла українська мова
  папки слід перенести перед випуском;
- пакет документів має стабільні заголовки та один H1 на сторінку;
- відносні посилання вирішуються в корені документів пакета;
— dDocs індекс/кеш було оновлено після змін файлу.

## Дані підтримки для збору

Коли проблема потребує глибшого розгляду, зберіть:

- версія PHP і включені драйвери бази даних;
- Evolution CMS версія або гілка;
- версія інсталятора та використовувана команда;
- тип бази даних і те, чи виникає проблема до чи після міграції;
- мова менеджера;
- змінені параметри системи, пов’язані з кеш-пам’яттю, URL-адресами, шляхами, завантаженнями чи дозволами;
- точна дія менеджера або URL-адреса, яка не вдається;
- останні встановлення або оновлення пакетів.
