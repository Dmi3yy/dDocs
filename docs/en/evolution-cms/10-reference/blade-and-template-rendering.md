# Blade And Template Rendering Reference

[Back](roles-and-permissions.md) / [Up](../README.md) / [Next](parser-tags.md)

Evolution CMS supports both classic Evolution parser templates and Blade-backed
templates. The current runtime chooses the rendering path from the resource
template and the available Blade view mapping.

## Rendering Flow

| Step | Runtime Behavior |
| --- | --- |
| Load resource | Core loads the resource object, validates deleted/published/reference state, and prepares document data. |
| Resolve template | Runtime asks the template processor for a Blade document view. If none is available, it loads template code from the database. |
| Share data | Blade templates receive `modx`, `documentObject`, and view data from the runtime. |
| Render Blade | If a Blade view exists, it is rendered by the view factory and the resource is treated as non-cacheable for that pass. |
| Parse classic template | If no Blade view exists, the classic template code is parsed by the Evolution parser. |
| Invoke events | `OnLoadWebDocument` runs after document content is prepared. Output events and post-parse behavior run later in the response flow. |

If a resource has no assigned template, the runtime uses `[*content*]` as a
blank classic template.

## Template Sources

| Source | Syntax Or Surface | Notes |
| --- | --- | --- |
| Database template | Manager Template element | Classic Evolution parser template. |
| Blade document view | Template processor resolved view | Current Blade path for resource templates. |
| Template file created on save | Manager template option | Template save can create a corresponding `.blade.php` file. |
| `@FILE` chunk/template mode | `@FILE:path` | Reads a template file under the configured template path and extension. |
| `@CODE` / `@INLINE` / `@TPL` | Inline code string | Used by parser chunk/template helpers. |
| `@DOCUMENT` / `@DOC` | Document content by id or current document | Pulls document content into parser templates. |
| `@B_FILE` | Blade file mode | Renders a Blade file through the cloned view factory. |
| `@B_CODE` | Blade code mode | Writes a generated Blade cache file and renders it through a `cache::` namespace. |

## Blade Data

Blade document templates receive the current runtime object and document data.

| Variable | Meaning |
| --- | --- |
| `$modx` | Current Evolution CMS core/runtime object. |
| `$documentObject` | Current resource object data. |
| View data | Additional runtime data prepared by `getDataForView()`. |

When the `DLTemplate` chunk processor is active, the same shared data is also
passed into its Blade integration.

## Manager Blade Views

The manager UI uses Blade views under the manager view namespace.

| View Pattern | Purpose |
| --- | --- |
| `manager::template.page` | Standard manager page shell. |
| `manager::template.blank` | Minimal manager page shell. |
| `manager::partials.header` | Manager header assets and top scripts stack. |
| `manager::partials.footer` | Manager footer and bottom scripts stack. |
| `manager::partials.actionButtons` | Standard manager page action buttons. |
| `manager::form.*` | Shared manager form rows, inputs, radio controls, selects, and textareas. |
| `manager::page.*` | Manager page screens and nested page partials. |

Common Blade stacks used by manager views include `scripts.top` and
`scripts.bot`.

## Core Blade Directives

| Directive | Output |
| --- | --- |
| `@evoConfig($key)` | Escaped value from `evo()->getConfig($key)`. |
| `@makeUrl($value)` | Escaped URL generated by the URL processor. |
| `@evoParser($value)` | Parsed Evolution content through `evo_parser()`. |
| `@evoRole($role)` | Opens a conditional block when `evo_role($role)` is true. |
| `@evoElseRole($role)` | Adds an `elseif` branch for another role check. |
| `@evoEndRole` | Closes the role conditional block. |
| `@auth` | True when `evo()->getLoginUserID()` is not false. |
| `@guest` | True when no frontend user is logged in. |
| `@svg($name, ...)` | Renders a Blade Icons SVG through the Evolution adapter. |

Legacy custom directives can still be registered from `view.directive`, but
that path is deprecated and should not be used for new product documentation.

## Support Directive Helpers

The support helper class also defines legacy directive callbacks used by older
config-driven directive registration:

| Helper | Meaning |
| --- | --- |
| `csrf()` | Outputs a CSRF field. Deprecated. |
| `evoLang($key)` | Reads a manager lexicon value. |
| `evoStyle($key)` | Reads a manager style value. |
| `evoAdminLang()` | Reads the active manager language name. |
| `evoCharset()` | Reads the manager charset. |
| `evoAdminThemeUrl()` | Reads the manager theme URL. |
| `evoAdminThemeName()` | Reads the manager theme name. |

New manager pages should prefer current manager helpers and shared views instead
of adding new config-driven directives.

## Blade Icons

Evolution CMS ships an adapter for Blade Icons. The adapter:

- merges the core `blade-icons` config;
- registers the icon factory and manifest;
- registers the `@svg` directive;
- registers icon components when the icon manifest exists;
- publishes `blade-icons.php` config in console mode.

Use icons through the configured icon sets and keep manager UI icon names stable
when package docs or screenshots refer to them.

## Documentation Rule

When documenting template behavior, state whether the example is classic parser
syntax or Blade syntax. Do not mix parser tags and Blade directives in the same
example unless the page explicitly explains how the two rendering paths interact.
